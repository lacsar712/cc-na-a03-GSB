# 航标灯光巡检台

登记航标实测光强和方位偏差，服务端当场给出合格或不合格。页面由 Django 模板直接渲染，浏览器不另跑一套单页应用。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3190 |
| 应用 | http://localhost:8190 |
| PostgreSQL | localhost:54390 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| keeper | light123456 | 可登记 |
| watch | watch123456 | 只读 |

## 启动

```bash
cd projects/11-nav-aid-inspection
docker compose up --build
```

## 验收

1. 打开 http://localhost:3190 ，用 keeper 登录，列表里 LH-01 合格、LH-09 不合格。
2. 再登记一条光强低于要求的记录，结论为光强不足。
3. 换 watch 登录，没有登记入口；直接提交登记会拒绝。
4. 顶栏点「逾期灯」：交卷基线天数门槛为 0，偏暗灯 LH-09 已在逾期现表，大事记有一条 LH-09（记下当时门槛 0 天、所依不合格实测和进入时刻），状态逾期中。
5. keeper 可直接在该页改天数门槛，保存后立即重新归并；watch 只能看，不能改（POST 被拒）。
6. 用 keeper 为 LH-09 补登记一条合格实测，再打开逾期灯：现表中 LH-09 消失，大事记原记录仍在并显示「已解除」。

## 逾期规则

- 天数门槛单独保存在逾期设置里（单值），持灯账号可改，改完下一次打开页面立即生效。
- 逾期现表按灯号归并：每盏灯只看最近一次实测，仍为不合格且距登记超过天数门槛（门槛 0 表示立即逾期）才收进现表。
- 灯首次进入现表时写入一条大事记，记录灯号、当时天数门槛、所依不合格实测主键和进入时刻。
- 后来补上合格实测（或门槛调高后不再逾期），现表去掉该灯，大事记保留并标记解除时刻。
